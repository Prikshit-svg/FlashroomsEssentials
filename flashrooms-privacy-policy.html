FlashRooms Privacy Policy

Last updated: October 12, 2026

Developer review required before publication

This draft is based only on the information currently provided: FlashRooms uses Firebase Authentication, a local Room database, and a hotel API; it is currently intended for browsing hotels; and Google AdMob is not yet integrated. The exact hotel API provider, specific data fields, retention periods, and deletion workflow have not been confirmed. Verify these details in the app and update this policy before using it as the live policy.

1. About FlashRooms

FlashRooms is an Android application for browsing and searching hotel information. For privacy questions, contact flashroomsadmin@gmail.com.

2. Information that may be processed

The information processed depends on the features you use and how the app is configured. Based on the services identified for the current version, the following categories may be relevant:

  • Firebase Authentication: if you sign in or create an account, Firebase Authentication may process account identifiers and the authentication details required by the sign-in method enabled in the app. The exact sign-in methods and fields must be confirmed by the developer.
  • Hotel searches and API requests: search terms, destination or other query details may be sent to the hotel API when you search or request hotel information. The API provider may also receive technical information associated with a request, such as an IP address, according to its own systems and privacy policy. The exact provider and fields sent by FlashRooms must be confirmed.
  • Local app data: the app uses Room Database, an on-device database. The particular information saved there, how long it remains, and whether it can be removed by clearing app data must be confirmed from the app's implementation.

Do not assume that FlashRooms collects a name, phone number, precise location, payment details, or booking information unless the current implementation actually collects or transmits it. FlashRooms is currently described as a hotel-browsing app, not as a service that completes hotel bookings.

3. How information is used

Depending on the implemented features, information may be used to authenticate users, respond to hotel searches, display hotel information, and store app data locally. The developer should verify these purposes against the actual app behavior and remove any statement that does not apply.

4. Third-party services and sharing

FlashRooms currently uses the following services, as reported by the developer:

  • Firebase Authentication: used for authentication. Google's processing is subject to the applicable Google Privacy Policy and Firebase terms and documentation.
  • Hotel API: used to retrieve hotel information. The provider's name and privacy-policy URL have not yet been supplied. Add them here before publication and describe the information sent in API requests.
  • Room Database: used for local on-device storage. Room is an Android database library; it does not by itself mean that stored data is sent to a third party.

Google AdMob advertising is not integrated at the time this draft was prepared. If advertising, analytics, crash reporting, maps, payment services, or any other SDK is added later, this policy and the relevant app-store disclosures must be reviewed and updated before or when those features are introduced.

The Android permissions requested by the current app have not been provided. The developer must inspect the app manifest and runtime permission requests and update this section to list any relevant permissions and explain their purpose. 6. Data security

Reasonable technical and organizational measures should be used to protect information handled by the app and its service providers. Data sent over the network should use HTTPS where supported. No method of transmission or storage can be guaranteed to be completely secure. The developer should verify the app's actual network security and access controls before publication.

7. Data retention and deletion

The exact retention periods for Firebase Authentication data, hotel API request data, and locally stored Room data have not yet been confirmed. Local data may remain on the device until it is removed by an app feature, app-data clearing, or uninstalling the app; this depends on the implementation and backups. Uninstalling the app does not necessarily delete data held by Firebase or the hotel API provider.

Before publication, specify how a user can request deletion of their account and associated server-side data, if accounts are supported, and how local and provider-held data are handled. Contact flashroomsadmin@gmail.com for privacy questions or to ask about data deletion. Do not describe email as a completed deletion process unless requests are actually handled and the process is operational.

The intended age group for FlashRooms has not been confirmed. The developer should establish the app's target audience and applicable requirements before publication. Do not use this draft as a statement that the app is designed for children or that it knowingly collects children's personal information.
